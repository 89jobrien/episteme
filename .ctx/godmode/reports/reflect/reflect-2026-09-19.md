## Patterns & Surprises

### Took longer than expected

- Model-generated evidence quotes remained paraphrased even with BAML structure and stronger local
  models. The reliable solution required redesigning evidence around deterministic source span IDs.
- The first real Crux publish attempts exposed two orchestration interactions: 1Password is
  unnecessary for dry-runs, and a workspace-root release state file makes Cargo consider the package
  dirty. Both needed TDD fixes in the plugin.

### Went smoothly

- Red-green-refactor tests consistently exposed missing APIs, unsafe staging behavior, packaging
  metadata, and release orchestration defects before publication.
- Independent architecture, security, quality, and release reviews found concrete issues that were
  resolved before merge.
- Final Cargo, live-model, package, Crux, crates.io, tag, and GitHub release verification all passed.

### Discovered mid-session

- The crates.io name `episteme` belongs to an unrelated knowledge-graph project, so this package was
  released as `episteme-local` while retaining `episteme` as the binary and library name.
- Crates.io publication makes package source public even when the GitHub repository remains private;
  local vault data, configuration, and model traffic remain excluded.
- The existing crates.io `episteme` crate offers graph and search concepts worth considering later,
  but its broad dependency surface does not belong in the initial release.

### Next session speedups

- Keep release state under ignored build state from the outset; never create release bookkeeping in
  the package root before `cargo publish`.
- Validate model semantics with one representative live case before scaling a prompt design across a
  batch; typed output does not imply grounded content.
- Check crates.io name ownership and package visibility constraints before writing release metadata.
